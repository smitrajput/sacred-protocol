# Contracts and code

Two systems appear in these docs, and only one exists.

| | Proposed | Existing |
| --- | --- | --- |
| **What** | MarginVault, SIFT ledger and capacity controller, CashFinanceVault | Term-mode vault, desk, price reader, funds, token side |
| **Where** | Arc, not deployed | Arbitrum One, Monad testnet |
| **Economics** | Everything in these docs | The first design's dials, listed below |
| **Status** | Specified, not built | Verified on block explorers. Not audited |

**The proposed engine is pending implementation.** It has no addresses, no tests and no audit. The controls in [Architecture](/docs/architecture) are requirements, not code. The inspected `contracts/src/Desk.sol` is a term-mode implementation and not this system. No test count below applies to it.

The rest of this page documents the existing deployment.

### Monad testnet

Monad testnet (chain 10143): the same contracts, deployed by `script/DeployMonadTestnet.s.sol` on 2026-10-14 and verified on MonadScan. Every SCR-side contract but the pool hook sits at the same address as on Arbitrum One. The testnet has no native USDC, WBTC or WETH, no Chainlink feeds and no Uniswap v3, so the desks trade against test stand-ins: tokens anyone can mint, price feeds anyone can set (seeded at BTC $83,180 and ETH $2,499 from Chainlink on Arbitrum One), and a router that swaps at the set price. The oracles accept a year-old price, since the feeds only move when someone sets them. The SCR pool runs on the Monad-maintained Uniswap v4 `PoolManager`. Testnet prices are not a reference.

### Live on-chain state

<LiveChain />

The deployed version pairs a vault with each desk, so two vaults exist.

Ownership is an OpenZeppelin `TimelockController` with a 2-day delay that only a multisig can propose to and execute from. A guardian can pause new positions and new deposits, and cannot unpause. Exits are never pausable by anyone.

## The rules the existing code keeps, and where each is tested

| Rule | How | Test |
| --- | --- | --- |
| The vault owns the asset before it sells it | `open` lends the full cost and swaps before it records the sale or takes the down payment | `test_open_recordsTheDesignExample` |
| A balance never increases | No function adds to `financed` or `markup`, or subtracts from `repaid` | `invariant_aBalanceNeverIncreases` |
| The vault never receives more than the settlement amount | `_payVault` pays `settlementAmount` on close and pay off, `min(net, balance)` on settlement | `invariant_vaultNeverReceivesMoreThanTheBalance` |
| The trader never owes more than the pledged asset | `settle` never pulls from the trader; a short sale closes the debt | `invariant_settlementNeverChargesTheTrader` |
| Only the trader can sell before the due date | `settle` reverts until the due date; there is no other sale path | `test_noOneCanSellBeforeDueExceptTheTrader` |
| A pledged asset leaves only to its owner or the market | `payOff` and `_swap` are the only asset transfers | `invariant_deskHoldsOnlyPledgesAndOwedSurpluses` |
| Exits cannot be paused | Only `open` and `requestDeposit` check the pause flag | `test_deposit_pausedByGuardian_withdrawalsStillWork` |
| Shares cannot be transferred | `transfer`, `transferFrom` and `approve` always revert | `test_shares_cannotBeTransferredOrApproved` |
| Every USDC is counted exactly once | Four counters; the vault never reads its own balance, so donations cannot move the share price | `invariant_vaultIsFullyBacked` |
| The admin cannot leave coded limits or touch live positions | Bounds in every setter; position terms are stored at opening | `test_admin_cannotExceedHardLimits` |

## Deployed dials

## Run it

```sh
anvil                                                                           # 1
cd contracts && forge script script/DeployLocal.s.sol --rpc-url http://127.0.0.1:8545 --broadcast
cd .. && python3 export_abi.py
cd server && KEEPER_KEY=<anvil key> .venv/bin/python -m destiny.keeper          # 2
cd server && .venv/bin/uvicorn --factory destiny.api:app_from_env               # 3
cd frontend && npm run dev                                                      # 4
```

The local deployment is the whole system with mocks for USDC, WBTC, the feed and the spot market, and a real `PoolManager`. The deployer holds 1,000,000 USDC and the genesis SCR, and must deposit 5% into the vault before anyone else can. Tests: `forge test` in `contracts/` (libraries cloned per the README), `pytest` in `server/`, `npm test && npm run test:e2e` in `frontend/`.
